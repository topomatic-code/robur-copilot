# Robur Copilot

Robur Copilot - профиль Hermes-агента, выступающий в качестве ассистента по работе с CAD-платформой Topomatic Robur.

## Установка профиля

1. Установите плагин `robur_mcp.tpm` при помощи `TopomaticPackageManager.exe`

2. Установите Hermes Agent:

```bash
 https://hermes-agent.nousresearch.com/
```

3. В установленном Hermes Agent откройте терминал (правый нижний угол) и выполните:

```bash
hermes profile install https://github.com/topomatic-code/robur-copilot --alias
```

Подтвердите установку в терминале [Y]. Закройте Hermes Agent.

4. Запустите модуль Robur и выполните команду `mcp_run`

5. Запустите Hermes Agent и выберите профиль `robur_copilot` в левом нижнем углу.

6. Выберите провайдера и используемую ИИ-модель.

Теперь вы можете использовать ИИ-агентов в своих проектах Robur.

## Обновление профиля

1. В Hermes Agent откройте терминал (правый нижний угол) и выполните:

```bash
hermes profile update robur_copilot
```

Hermes загрузит обновление из репозитория, указанного при установке профиля. Если при установке вы задали другое имя через `--name`, используйте его вместо `robur_copilot`.

2. Проверьте сведения об установленном профиле:

```bash
hermes profile info robur_copilot
```

Команда покажет версию профиля и адрес исходного репозитория.

3. Перезапустите Hermes Agent и выберите профиль `robur_copilot` в левом нижнем углу.

При обновлении:

- `SOUL.md`, `skills/` и `distribution.yaml` заменяются файлами из репозитория; локальные правки в этих файлах следует предварительно сохранить отдельно;
- локальный `config.yaml`, включая выбранную модель и провайдера, сохраняется по умолчанию;
- память, история сессий, API-ключи и другие пользовательские данные сохраняются.

Если нужно также заменить локальный `config.yaml` конфигурацией из репозитория, выполните:

```bash
hermes profile update robur_copilot --force-config
```

Параметр `--force-config` перезапишет локальные настройки в `config.yaml`. После этого проверьте выбор провайдера и модели.

Подробнее: [Profile distributions](https://hermes-agent.nousresearch.com/docs/user-guide/profile-distributions#update) - официальная документация Hermes по обновлению профилей.

## Назначение

Профиль настраивает Hermes как специализированного ассистента для задач вокруг Topomatic Robur:

- работа с активным проектом Topomatic Robur;
- работа с активным чертежом Topomatic Robur;
- твердотельное моделирование в активном чертеже;
- работа с Tlc-скриптами и параметрическими Tlc-моделями.

Профиль не привязан к конкретному провайдеру или модели. Модель, API-ключи и параметры доступа задаются в локальном окружении пользователя, который устанавливает дистрибутив.

## Скиллы

- `alg-construction` - анализ конструкций поперечных профилей автомобильной дороги, участков назначения и зависимостей от параметров трассы.
- `project-assistant` - скилл для безопасной работы со структурой активного проекта, моделями, вкладками и видами Robur.
- `tlc-assistant` - основной скилл для консультаций, обучения и написания Tlc-скриптов.

## Файлы дистрибутива

- `distribution.yaml` - метаданные Hermes profile distribution и список файлов, которыми владеет дистрибутив;
- `SOUL.md` - описание роли и поведения агента;
- `config.yaml` - базовая конфигурация профиля;
- `skills/` - скиллы профиля;
- `.gitignore` - исключения для секретов, runtime-состояния, кешей и локальных пользовательских данных.

## Правила работы с SOUL.md и SKILL.md

`SOUL.md` задает верхнеуровневую личность, стиль, общие принципы поведения агента и маршрутизацию к скиллам. В нем не следует подробно описывать предметные workflow, команды, структуру документации или алгоритмы работы с конкретным доменом.

`SKILL.md` задает специализированное поведение для конкретной области. В нем нужно держать инструкции по чтению документации, проверке результата, использованию инструментов, ограничениям домена и практическому порядку работы.

Чтобы профиль оставался поддерживаемым:
- не дублируйте подробные инструкции между `SOUL.md` и `SKILL.md`;
- в `SOUL.md` оставляйте только правило маршрутизации к нужному скиллу и общие границы поведения;
- в `SKILL.md` держите единственный источник правды по предметному workflow;
- если меняется устройство локальной документации скилла, обновляйте ссылки и проверяйте, что markdown-ссылки ведут на существующие файлы;
- описание скилла в frontmatter делайте коротким и понятным, без перечисления всех деталей поведения.

## Выпуск релизной версии

Каждая релизная версия профиля должна иметь Git-метку в формате `vMAJOR.MINOR.PATCH`, соответствующую полю `version` в `distribution.yaml`: например, для `version: 0.2.0` создаётся метка `v0.2.0`.

Порядок выпуска:

1. Обновите `version` в `distribution.yaml` и создайте коммит с готовыми изменениями профиля.
2. Поставьте на этот коммит метку с соответствующей версией.
3. Опубликуйте изменения в основной ветке репозитория и отправьте созданную метку на сервер.

Это обязательное правило проекта основано на рекомендации официальной документации Hermes: [Step 5 — Tag versioned releases](https://hermes-agent.nousresearch.com/docs/user-guide/profile-distributions#step-5--tag-versioned-releases).

Метка фиксирует релиз в истории Git. Команда `hermes profile update` загружает текущее состояние ветки репозитория по умолчанию, а не выбирает последний тег, поэтому сама по себе метка не ограничивает обновления только релизными версиями.
