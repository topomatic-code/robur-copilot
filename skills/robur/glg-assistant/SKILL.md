# Geology Assistant

Используй этот скилл для работы с геологическими моделями и выработками Robur, в том числе при поиске нарушений порядка групп напластований перед построением 3D-модели геологии.

## Выбор модели и инструментов

Используй фактически доступные MCP-инструменты домена `[ГЕОЛОГИЯ]`. Ниже приведены базовые имена; если MCP добавляет префикс сервера, вызывай соответствующие доступные инструменты по их фактическим схемам. Если инструмента нет или вызов завершился ошибкой, сообщи об ограничении, не выдавая это за отсутствие проблем в модели.

Получи дерево через `project_get_active` и выбери геологическую модель по актуальным `name`, `type`, `typeDescription` и `pathId`. Не конструируй PathId из имени или пути к файлу. При неоднозначности уточни модель; для запроса по всем моделям обработай каждую отдельно, сохраняя их идентичность в отчете. Для выбора контекста проекта загрузи скилл `project-assistant` через `skill_view(name="project-assistant")` и следуй его инструкциям. Если скилл уже загружен в текущем контексте, повторная загрузка не нужна.

| Задача | Инструмент | Передаваемые идентификаторы |
|---|---|---|
| Название модели и перечень выработок | `glg_get_info` | `pathId` модели |
| Сведения об одной выработке | `glg_get_borehole` | `glgPathId` модели и `boreholeId` выработки |
| Послойный список грунтов выработки | `glg_get_borehole_grounds` | `glgPathId` модели и `boreholeId` выработки |
| Проверка групп во всех выработках модели | `glg_get_invalid_bedding_groups` | `glgPathId` модели |

Для выбора выработки по номеру используй `boreholes` из `glg_get_info`: в каждом элементе есть `id` и `number`. Передавай GUID `id` в `boreholeId`, не подменяй его номером. Номер не гарантирует уникальность; при совпадениях уточни нужную выработку. Ответ `glg_get_info` также содержит `name` и `boreholeCount`.

Выбирай вызовы по задаче:

- Для общих сведений о выработке вызывай `glg_get_borehole`.
- Для состава грунтов, их глубин, мощностей и групп напластований вызывай `glg_get_borehole_grounds`; предварительный вызов `glg_get_borehole` не нужен, если GUID выработки уже известен.
- Для массовой проверки сразу вызывай `glg_get_invalid_bedding_groups` после выбора модели. Не запрашивай сведения о тысячах выработок по одной: проверка сама обходит всю таблицу.
- Для разбора конкретного нарушения получи грунты нужной выработки через `glg_get_borehole_grounds`, используя ее `id` из результата проверки. Сведения шапки запрашивай отдельно, если для анализа нужны координаты, тип или другие признаки выработки.

Все инструменты геологии в этом скилле читают данные и не изменяют модель. Ответы имеют оболочку `result`, `description`, `status`; предметные данные находятся в `result`.

## Сведения о выработке

`glg_get_borehole` возвращает поля шапки таблицы выработок:

| Поле результата | Значение в интерфейсе |
|---|---|
| `id`, `number` | GUID и номер выработки |
| `type` | Тип выработки — строковое имя значения `BoreholeType` |
| `marked` | Помеченная |
| `boringDate` | Дата бурения, строка из модели |
| `elevation` | Отметка, м |
| `archiveNumber` | Архивный номер |
| `seasonFrostDepth` | Глубина промерзания, м |
| `seasonThawingDepth` | Глубина оттаивания, м |
| `depth` | Общая глубина, м |
| `coordinates.easting`, `coordinates.northing` | Восточная и северная координаты, м |
| `description` | Описание выработки |
| `drillingEquipmentType` | Вид буровой установки |
| `constructionType` | Вид сооружения |
| `bulkCalculate` | Учитывать при расчете 3D |
| `isFictive` | Фиктивная |

Логические признаки возвращаются как `bool`; для пользователя их можно показать как «Да»/«Нет». Незаданные глубины промерзания и оттаивания имеют значение `null`, а не ноль. Не интерпретируй пустую дату как известную дату и не округляй координаты в исходных данных отчета. Координаты заданы в метрах; инструмент не сообщает систему координат, поэтому не трактуй их как широту и долготу.

Послойный состав получай отдельным вызовом `glg_get_borehole_grounds`, а не восстанавливай по общей глубине выработки.

## Грунты выработки

`glg_get_borehole_grounds` возвращает `result.id` и `result.number` выработки, `groundCount` и массив `grounds`. Это строки грунтов выбранной выработки в исходном порядке сверху вниз, а не каталог всех грунтов геологической модели. `groundCount` — число строк, включая повторные вхождения одного грунта.

| Поле элемента `grounds` | Смысл |
|---|---|
| `rowNumber` | Номер строки выработки, начиная с 1 |
| `id` | GUID назначенного грунта |
| `cipher`, `name` | Шифр и название назначенного грунта |
| `beddingGroup` | Группа напластований назначенного грунта |
| `depth` | Глубина из строки выработки, м |
| `power` | Мощность слоя, м |
| `description` | Описание в строке выработки |
| `excavationCategory` | Категория разработки в строке выработки |
| `genesis` | Генезис в строке выработки |

Различай свойства назначенного грунта (`id`, `cipher`, `name`, `beddingGroup`) и его вхождения в выработку (`depth`, `power`, `description`, `excavationCategory`, `genesis`). Не выдавай описание строки за описание грунта из общего каталога. `depth` здесь относится к строке; `result.depth` у `glg_get_borehole` — общая глубина выработки.

Сохраняй исходные `rowNumber` и порядок строк. Не сортируй список по группе, шифру или глубине и не удаляй повторяющиеся GUID: это скроет расположение грунтов и может скрыть нарушение порядка групп. Пустой `grounds` при `groundCount = 0` означает отсутствие строк грунтов, а не отсутствие самой выработки.

Для анализа нарушения сопоставляй `invalidGrounds.rowNumber` с `grounds.rowNumber`, а `precedingMaxBeddingGroupRow` — со строкой предшествующего максимума. Учитывай также модель и GUID выработки. Так можно показать оба грунта и промежуточные строки, а не только ошибочную группу. Если между вызовами модель изменилась и строки или значения не совпадают, обнови проверку перед выводом.

## Проверка групп напластований

Порядок проверяется по строкам грунтов в каждой выработке сверху вниз. Значения `BeddingGroup` должны идти в **неубывающем** порядке: одинаковые группы допустимы. Не требуй начала с 0 или 1, последовательных целых значений либо строго возрастающих групп.

Инструмент отмечает каждую строку, группа которой меньше максимальной группы среди всех предшествующих строк, а не только предыдущей строки:

- `0 → 1 → 1 → 2` — ошибок нет;
- `1 → 0 → 0` — проблемные строки 2 и 3;
- `0 → 3 → 1 → 2 → 3` — проблемные строки 3 и 4; строка 5 допустима.

Проверка охватывает все выработки модели, независимо от `marked`, `bulkCalculate` и `isFictive`. Пустая выработка или выработка с одной строкой не нарушает порядок и не попадает в список. Проверка не оценивает полноту данных таких выработок.

В `result` возвращаются:

- `invalidBoreholeCount` — количество проблемных выработок, не количество ошибок или уникальных грунтов;
- `boreholes` — только проблемные выработки; каждая содержит `id`, `number` и массив `invalidGrounds`.

Каждый элемент `invalidGrounds` описывает конкретное вхождение грунта в выработку:

| Поле | Смысл |
|---|---|
| `rowNumber` | Номер проблемной строки, начиная с 1 |
| `id` | GUID грунта, не выработки |
| `cipher`, `name` | Шифр и название грунта |
| `beddingGroup` | Группа в проблемной строке |
| `precedingMaxBeddingGroup` | Максимальная группа выше этой строки |
| `precedingMaxBeddingGroupRow` | Первая строка, где достигнут этот максимум, начиная с 1 |

`invalidGrounds` содержит только нарушения, а не весь разрез. Для локализации нарушения сохраняй модель, `id` выработки и `rowNumber` вместе с данными грунта; для полного состава используй `glg_get_borehole_grounds`.

## Результат для геолога

Назови проверенную модель и число проблемных выработок. Покажи по каждой выработке номер и id, а для каждого нарушения — строку, шифр/название и id грунта, текущую группу и предшествующий максимум с его строкой. Если считаешь суммарное количество нарушений, считай элементы `invalidGrounds` и явно отличай его от количества выработок.

При большом результате сначала дай сводку. Если показываешь лишь часть строк, обозначь ее как выборку и укажи полный счетчик; не представляй сокращенный ответ как полный список. При подготовке файла отчета сохраняй все полученные нарушения и идентификаторы.

Если `invalidBoreholeCount = 0` и `boreholes` пуст, сообщи: «Все выработки корректны по порядку групп напластований». Это результат только данной проверки, а не подтверждение геологической достоверности или полной корректности 3D-модели. Для пустой модели, если это известно из `glg_get_info`, уточни, что выработок нет.

Список указывает на нарушения порядка, но не определяет, какую именно группу следует исправить. Причиной может быть и неверная группа в более ранней строке. Не предлагай механически присваивать всем отмеченным грунтам предшествующий максимум или сортировать строки: это может изменить геологический смысл разреза.

Геолог должен проанализировать результат и выбрать исправление: изменить группу напластований либо создать дополнительный грунт в «Модель Геологии — Грунты» и переназначить грунт в выработке. Доступные здесь инструменты этих изменений не выполняют. После сообщенных пользователем исправлений повтори проверку и сравни актуальные результаты.

## Проверка отчета

Для списка грунтов проверь соответствие выбранной выработке, количества строк `groundCount` и массива `grounds`. Для отчета о нарушениях проверь, что количество полученных проблемных выработок соответствует `invalidBoreholeCount`, а у каждой показанной строки `beddingGroup < precedingMaxBeddingGroup`. Несоответствие или усечение ответа не трактуй как успешную полную проверку. Используй фактические данные последнего вызова и отделяй обнаруженные нарушения от предположений об их причинах.
