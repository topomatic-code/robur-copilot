# Project Assistant

Используй этот скилл для выбора контекста любой практической работы в Topomatic Robur: структуры проекта, активной модели, вкладки, вида, чертежа и видового экрана. Он также задает порядок создания папок, удаления, перемещения, переименования и переупорядочивания элементов проекта.

## Модель активного проекта

Структура проекта, модели и вкладки — ключевые механизмы работы с Robur. Дерево определяет, с каким элементом работаешь, а активная модель и вкладка — контекст доступных операций. Активный проект представлен деревом папок, моделей и статических файлов. Не отождествляй его с файловой системой: структура, идентичность и жизненный цикл элементов контролируются Robur.

В дереве пользователь может назначить активную модель. В интерфейсе ее имя выделяется жирным шрифтом. Активная модель задает основной контекст проектных вкладок, но сама по себе не равна активному чертежу, вкладке или видовому экрану.

Вкладки открывают окна редактирования и просмотра — виды (`View`). Различай:

- системные вкладки «План» и «3д-вид» — общие для всех моделей проекта. «3д-вид» дополняет «План» и является его 3D-представлением;
- вкладки модели — представляют ее специальные виды; их набор зависит от активной модели. Например, у дороги есть виды продольного профиля и поперечников;
- динамические вкладки создаются для отдельной задачи и не обязательно привязаны к активной модели. При ее смене они могут сохраняться до закрытия пользователем или перезапуска Robur. Примеры — просмотр или редактирование чертежа либо ведомости и быстрое сечение поверхности.

В общем «Плане» пользователь видит примитивы планов всех моделей и их неявных чертежей, но запрос активного чертежа возвращает только неявный чертеж активной модели. Примитивов других моделей в нем нет: содержимое этого чертежа не совпадает со всем, что отображается в «Плане».

Некоторые модели, включая поверхности и дороги, неявно содержат собственные чертежи. Для чтения или редактирования конкретного неявного чертежа активируй его модель и соответствующую вкладку. При переходе с «Плана» на «Профиль» активный чертеж может меняться. Не считай путь модели или узел проекта самостоятельным статическим чертежом.

Вкладка может предоставлять видовой экран (`CadView`) для интерактивного ввода геометрии и управления отображаемой областью, а также чертеж для операций с его сущностями. Доступность этих возможностей определяй по флагам окна, а не по его названию или видимым примитивам.

## Работа со структурой проекта

Для работы со структурой проекта используй инструменты, отмеченные доменом `[ПРОЕКТ]`, если Robur MCP доступен. Ты должен опираться на фактические результаты инструментов, а не на догадки о состоянии Robur.

Доступные операции:

- `project_get_active` — получить имя и полное дерево активного проекта. Каждый узел содержит `name`, `uri`, `relativePath`, `type`, `typeDescription` и `children`;
- `project_create_folder` — создать папку у родительского элемента по `parentUri`;
- `project_move_rename_item` — переименовать элемент либо переместить его относительным значением `newName`;
- `project_reorder_item` — сдвинуть элемент на одну позицию вверх или вниз среди соседей текущего уровня;
- `project_delete_item` — удалить элемент вместе со всеми вложенными элементами.

Перед операцией со структурой вызови `project_get_active`, найди целевой узел по актуальному дереву и используй его полный `uri`. Не конструируй URI вручную и не подменяй его значением `relativePath`. Если несколько узлов подходят под описание пользователя, уточни целевой элемент до изменения проекта.

После изменения структуры снова вызови `project_get_active`, когда нужно подтвердить итоговое расположение, имя, порядок или состав дерева. Не считай успешный вызов доказательством изменений, выходящих за пределы возвращенного результата.

`project_get_active` описывает дерево, но не возвращает признак активной модели, активную вкладку или тип текущего окна. Для выбора контекста используй инструменты активации ниже.

## Активация модели и работа с вкладками

Инструменты домена `[ПРОЕКТ]`:

- `project_activate_model` — активировать модель по `uri` из актуального дерева проекта, открыв ее при необходимости;
- `project_get_active_windows` — получить `windowCount` и список `windows`. У каждого окна есть `Name`, `UID`, `Dynamic`, `HasCadView` и `HasDrawing`;
- `activate_window` — активировать вкладку по параметру `uid`, взятому из ее `UID`;
- `close_window` — закрыть вкладку по `uid`. Закрывать можно только динамические вкладки (`Dynamic = true`).

Чтобы просмотреть вкладки конкретной модели, сначала активируй ее через `project_activate_model`, затем вызови `project_get_active_windows`. Список включает доступные системные вкладки и может включать сохранившиеся динамические окна: не приписывай все возвращенные вкладки выбранной модели. Выбери нужную вкладку по результату и передай ее `UID` в `activate_window`; при неоднозначности уточни выбор.

Список окон не содержит признака активной вкладки. Ее выбор подтверждается успешным `activate_window`, а выбор модели — `project_activate_model`. После смены модели заново получи список окон, прежде чем выбирать вкладку. Если нужного инструмента нет, попроси пользователя выполнить соответствующее переключение в Robur.

Закрывай вкладку только по задаче пользователя, проверив ее `UID` и `Dynamic` по актуальному списку. Не закрывай сохранившиеся динамические окна ради смены модели. После закрытия обнови список, если работа с вкладками продолжается.

### Контекст чертежа

Например, чтобы прочитать неявный чертеж плана автодороги, сначала вызови `project_activate_model` с `uri` модели дороги, затем получи окна через `project_get_active_windows` и активируй «План» через `activate_window`. Только после этого запрашивай активный чертеж и его содержимое. Одной видимости дороги в общем «Плане» недостаточно для выбора ее чертежа.

`HasDrawing = true` в актуальных данных окна означает, что оно содержит чертеж, с которым после активации вкладки можно работать всеми стандартными инструментами домена `[ЧЕРТЕЖ]`. Это относится и к неявным чертежам моделей. При `HasDrawing = false` не вызывай для этого окна инструменты чертежа. Флаг возвращается как в списке окон, так и в результате `activate_window`; `HasCadView` не заменяет эту проверку.

Используй `dwg_get_active_drawing_info`, когда нужны сведения о содержимом, границах или слоях выбранного чертежа. Для одной лишь проверки его наличия достаточно `HasDrawing`. Ошибка получения сведений не означает, что чертеж пуст.

При смене модели или вкладки заново установи контекст чертежа перед его чтением или редактированием. Не переноси в него автоматически ранее полученные сведения о слоях и сущностях: они могли относиться к другому чертежу.

## Ограничение на файловую систему

Не используй файловую систему, оболочку или обычные файловые API для чтения, создания, копирования, перемещения, переименования либо удаления элементов активного проекта. Это относится и к путям, полученным из `uri` или `relativePath`. Прямое изменение файлов может рассинхронизировать дерево и внутреннее состояние Robur, повредить проект или вызвать ошибки при дальнейшей работе.

Читай и изменяй структуру только через предназначенные для этого инструменты Robur MCP. Если требуемой операции нет среди доступных инструментов — например, отсутствует инструмент создания модели, добавления статического файла или чтения его содержимого, — сообщи об ограничении. Не обходи его прямым доступом к диску. При необходимости предложи пользователю выполнить такую операцию в интерфейсе Robur.

Ограничение относится к элементам активного проекта. Оно не запрещает работать с отдельными файлами разработки вне проекта Robur, когда пользователь явно поставил такую задачу и это не меняет структуру активного проекта.

## Работа с видовым экраном

Для взаимодействия с видовым экраном используй инструменты, отмеченные доменом `[ВИДОВОЙ ЭКРАН]`:

- `cad_view_get_point` — запросить у пользователя одну точку курсором. Обязательное поле `message` задает текст подсказки. Результат содержит координаты `x` и `y`;
- `cad_view_get_polygon` — запросить последовательность точек контура полилинии. Обязательное поле `message` задает текст подсказки. Результат содержит массив `positions` с координатами `x`, `y` и признак `closed`;
- `cad_view_zoom` — перенести и масштабировать видовой экран так, чтобы показать 2D-область между точками `min` и `max`.

Все координаты относятся к пространству текущего вида активной вкладки, которая может быть динамической. Не считай их глобальными координатами проекта и не переноси автоматически между моделями, вкладками или видами. Инструменты возвращают только `x` и `y`; не добавляй координату `z` без документированного правила или данных пользователя. Передавай полученные точки в другой инструмент только когда он ожидает координаты того же пространства.

### Интерактивный ввод

`cad_view_get_point` и `cad_view_get_polygon` временно передают управление пользователю для работы курсором. Перед вызовом:

1. Убедись, что точка или контур действительно нужны для текущей задачи.
2. Скажи пользователю, что сейчас потребуется ввод в Robur.
3. Передай в `message` короткую предметную инструкцию: что именно и в каком порядке нужно указать.

Не вызывай несколько интерактивных запросов заранее. Выполняй их последовательно и используй результат предыдущего ввода перед следующим запросом.

Для контура учитывай поле `closed`: замкнутость задается этим признаком, а не обязательным повторением первой точки в конце `positions`. Открытый контур может состоять из двух и более точек; замыкание доступно после ввода не менее трех точек.

Отмена пользователем является штатным исходом интерактивного ввода. Не повторяй отмененный запрос автоматически и не трактуй отмену как повреждение проекта. Останови зависящее от ввода действие и сообщи, что ввод не был завершен.

### Масштабирование вида

Для `cad_view_zoom` передавай `min` и `max` в координатах текущего вида. Формируй границы из фактической геометрии или результата инструмента, а не из приблизительных значений по памяти. `cad_view_zoom` изменяет только положение и масштаб отображения; он не изменяет модель, чертеж или структуру проекта.

### Доступность видового экрана

`HasCadView = true` у выбранного окна означает, что после его активации доступны операции `cad_view_*`. При `HasCadView = false` не применяй их к этому окну. Если задача относится к другой модели или виду, выбери подходящий контекст инструментами активации. После смены модели или вкладки считай прежний координатный контекст недействительным и при необходимости запроси точки заново.

## Выбор инструмента и порядок работы

Сначала определи операционный контекст задачи:

1. Для чтения или изменения дерева проекта используй инструменты домена `[ПРОЕКТ]`. Получи актуальную структуру через `project_get_active`, найди элемент по совокупности `name`, `relativePath`, `typeDescription` и положения в дереве, затем передай его `uri` в нужный инструмент.
2. Для просмотра, выбора или закрытия вкладок следуй разделу «Активация модели и работа с вкладками».
3. Для ввода точки или контура и для показа 2D-области выбери вкладку с `HasCadView = true` и используй инструменты домена `[ВИДОВОЙ ЭКРАН]`.
4. Для чтения или редактирования статического или неявного чертежа установи контекст по разделу «Контекст чертежа» и используй инструменты домена `[ЧЕРТЕЖ]`. Инструменты домена `[ВИДОВОЙ ЭКРАН]` получают ввод и управляют отображением, но сами не создают и не изменяют сущности чертежа.
5. Для 3D-сцены, таблицы, ведомости или специализированного вида сначала проверь наличие предназначенного для него инструмента. Не подменяй такую работу инструментами доменов `[ВИДОВОЙ ЭКРАН]` или `[ЧЕРТЕЖ]`.

Не вызывай `project_get_active`, если задача относится только к уже выбранному видовому экрану и структура проекта для нее не нужна. И наоборот, не требуй наличия видового экрана для операций, затрагивающих только дерево проекта.

После изменения структуры проверь ответ инструмента и при необходимости снова получи дерево проекта. После интерактивного ввода проверь форму результата, координатный контекст и `closed` для контура. После масштабирования достаточно успешного ответа инструмента, если пользователь не просит дополнительной проверки.

## Безопасность изменений

- Для диагностики структуры проекта сначала используй `project_get_active`: этот вызов не меняет проект.
- Создавай, перемещай, переименовывай и переупорядочивай элементы только когда этого требует запрос пользователя.
- Перед удалением проверь точный `uri` и состав `children`: `project_delete_item` удаляет все поддерево. Если из запроса не ясно, что вложенные элементы тоже должны быть удалены, сначала уточни намерение.
- Не повторяй изменяющий вызов автоматически после неоднозначной ошибки: сначала проверь фактическое состояние соответствующим инструментом — получи дерево, список окон или сведения о чертеже.
- Не обещай восстановление удаленного элемента, если доступный инструмент не предоставляет такую возможность.
- Вызовы `cad_view_*` не изменяют данные проекта, но могут требовать действий пользователя или менять текущую отображаемую область. Предупреждай об интерактивном вводе и уважай отмену.

## Стиль ответа

Используй термины Robur точно: «элемент проекта», «активная модель», «вкладка», «вид», «активный чертеж» и «видовой экран» обозначают разные сущности. Не называй элемент активным, если это не подтверждено результатом инструмента, доступным состоянием интерфейса или пользователем. Перед интерактивным вводом дай короткую понятную инструкцию, а после него сообщи, что было получено и в каком контексте это можно использовать. При ограничении инструментов прямо укажи, какую операцию нельзя выполнить безопасно и что пользователь должен сделать в интерфейсе Robur.
